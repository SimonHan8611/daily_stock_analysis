# 股票智能分析系统 PRD

## 1. 文档说明

- 文档名称：股票智能分析系统 PRD
- 适用范围：`daily_stock_analysis` 项目当前能力梳理与后续产品规划
- 文档目的：统一项目的产品定位、目标、功能范围与阶段性里程碑，作为后续需求讨论、设计拆解和版本规划的基础

## 2. 产品背景

股票投资用户在日常决策中通常面临以下问题：

- 信息来源分散：行情、新闻、公告、资金流、技术指标、社交舆情往往分散在多个平台，难以统一整理
- 分析成本高：用户需要手动收集信息、交叉验证，再形成自己的判断，过程耗时且重复
- 结果难落地：不少工具只能提供原始数据或单点信号，缺少结构化结论、风险提示和操作建议
- 跟踪验证不足：用户很难系统回看历史结论、复盘建议是否有效，并将分析结果与持仓、交易行为形成闭环
- 配置与部署门槛高：不同用户对模型、搜索、通知、运行环境需求不同，需要一个更统一的配置和运行入口

本项目的目标是将“数据获取、AI 分析、报告生成、通知分发、交互问答、历史验证”整合成一个统一工作台，帮助用户从“看数据”升级为“做决策”。

## 3. 产品定位

股票智能分析系统是一个面向个人投资者和进阶交易用户的 AI 投研辅助平台，覆盖 A 股、港股、美股，提供：

- 每日自动化股票分析与大盘复盘
- 手动触发的单股/多股分析
- 面向策略追问的 Agent 问股能力
- 历史报告、完整报告与回测验证
- 多账户持仓与交易事件管理
- 多渠道通知推送
- Web、API、Bot、CLI、Desktop 多入口协同

该产品定位为“投研与决策辅助系统”，不直接承担真实交易执行功能。

## 4. 产品目标

### 4.1 总体目标

- 为股票投资用户提供一个统一、结构化、可配置的 AI 分析平台
- 降低日常选股、盯盘、信息整理和复盘成本
- 通过历史记录和回测能力增强分析结果的可解释性与可信度
- 通过多端接入和多渠道推送提升产品触达效率

### 4.2 阶段目标

- 第一阶段：稳定完成每日自动分析、通知推送和基础 Web 查看能力
- 第二阶段：完善 Web 工作台，支持手动分析、历史报告、设置管理和多轮问股
- 第三阶段：建立用户体系与权限体系，支持多用户数据隔离和管理员配置
- 第四阶段：打通持仓、分析、回测之间的闭环，形成更完整的投资辅助流程

## 5. 目标用户

### 5.1 个人投资者

特征：

- 主要关注自选股和市场热点
- 希望每天快速获得结构化分析结果
- 不希望频繁切换多个数据平台

核心诉求：

- 自动接收分析报告
- 快速查看结论、风险和操作建议
- 需要简单易用的配置与查看方式

### 5.2 进阶交易用户

特征：

- 对策略、技术指标、市场节奏和消息面更敏感
- 需要主动发起分析、追问原因、查看完整报告与回测结果

核心诉求：

- 支持手动分析和多轮问答
- 支持历史复盘和策略有效性验证
- 支持多账户持仓管理

### 5.3 管理员/部署者

特征：

- 负责系统部署、配置、模型接入、用户管理和通知维护

核心诉求：

- 统一的系统配置入口
- 可管理用户与权限
- 可导入导出配置并追踪系统状态

## 6. 核心使用场景

### 6.1 每日自动分析

用户提前配置好股票池、模型、搜索源和通知渠道，系统在工作日定时执行分析，并将结果推送到企业微信、飞书、Telegram、Discord、Slack 或邮箱。

### 6.2 手动查看与单次分析

用户进入 Web 首页，输入股票代码或从历史中选择标的，查看分析结果，并进一步执行重新分析、完整报告查看或追问 AI。

### 6.3 策略问股

用户在问股页面发起多轮对话，结合内置策略技能与实时信息进行追问，获得更细致的策略解释和判断建议。

### 6.4 历史复盘与验证

用户查看历史报告，回看当时建议，并配合回测结果评估分析准确率和模拟收益情况。

### 6.5 组合与交易跟踪

用户建立多个持仓账户，记录买卖交易，后续与分析结果、回测结论联动，形成个性化投资管理闭环。

## 7. 功能清单

### 7.1 分析中心

- 支持单股分析和批量分析
- 支持同步分析与异步分析两种模式
- 支持股票代码标准化、去重和批量校验
- 支持分析任务状态管理和重复提交保护
- 输出结构化分析结果，包括结论、评分、风险、催化因素和建议

### 7.2 大盘复盘

- 支持 A 股、港股、美股及组合市场复盘
- 展示主要指数、涨跌统计、板块强弱、市场概况
- 支持独立运行复盘模式
- 支持与个股分析结果联合推送

### 7.3 Web 工作台

- 首页分析结果查看
- 历史报告选择与重看
- 重新分析、追问 AI、查看完整分析报告
- 支持浅色/深色主题
- 支持移动端与桌面端基础适配

### 7.4 历史报告中心

- 支持历史报告列表
- 支持完整 Markdown 报告查看
- 支持重新分析
- 支持批量管理与删除
- 支持结果回看与再次利用

### 7.5 Agent 问股

- 支持模型列表和策略技能列表
- 支持多轮问答
- 支持会话历史保存、读取和删除
- 支持研究模式
- 支持消息发送到通知渠道
- 支持流式响应能力

### 7.6 回测验证

- 支持对历史分析结果做事后验证
- 支持指定股票或指定时间窗口回测
- 输出方向准确率和模拟收益等结果
- 为后续策略优化提供数据基础

### 7.7 持仓管理

- 支持多持仓账户
- 支持账户创建、更新、停用
- 支持交易记录新增、查询、删除
- 支持按日期、账户、股票代码等条件筛选
- 为分析建议与投资执行的关联提供基础数据

### 7.8 系统设置

- 支持模型配置
- 支持数据源配置
- 支持通知渠道配置
- 支持回测与 Agent 相关参数配置
- 支持配置导入/导出
- 支持版本信息展示与桌面端更新提示

### 7.9 认证与权限

- 支持用户注册、登录、登出
- 支持基于 JWT + HTTPOnly Cookie 的会话机制
- 支持角色权限控制（至少包含管理员和普通用户）
- 支持管理员查看用户列表与启停用户
- 支持业务数据按用户隔离

### 7.10 Bot 与外部接入

- 支持飞书、Telegram、Discord、钉钉等 Bot 接入
- 支持通过 Bot 发起分析、查看结果或执行问股
- 支持外部平台账号与内部用户映射

### 7.11 运行与部署

- 支持本地 CLI 运行
- 支持 FastAPI 服务模式
- 支持 Web 前端工作台
- 支持 Electron 桌面端
- 支持 Docker 部署
- 支持 GitHub Actions 定时执行

## 8. 权限与角色边界

### 8.1 管理员

- 维护系统配置
- 管理模型、数据源和通知渠道
- 管理用户状态
- 查看和操作管理员专属设置页能力

### 8.2 普通用户

- 登录系统
- 进行手动分析与查看历史报告
- 使用问股功能
- 查看和维护自己的持仓数据
- 使用开放给普通用户的基础设置

## 9. 非功能需求

### 9.1 稳定性

- 单一股票分析失败不能影响整批任务结果
- 单一数据源失败不能拖垮主流程，需支持 fallback
- 单一通知渠道失败不能导致整次分析失败

### 9.2 安全性

- 密码必须加密存储
- 会话必须基于安全 Cookie 管理
- 配置项中的敏感字段必须脱敏展示
- 用户数据必须按账号隔离

### 9.3 可配置性

- 核心模型、通知、数据源、运行参数应支持环境变量和系统配置页双入口
- 新配置默认遵循“不配置也可运行，配置后增强”的原则

### 9.4 可观测性

- 鉴权、分析、通知、外部服务失败等关键节点需具备日志输出
- 任务执行状态应可通过 Web 或 API 进行查看

### 9.5 可扩展性

- 模型供应商可扩展
- 数据源可扩展
- 通知渠道可扩展
- Agent 技能和策略可扩展

## 10. 里程碑规划

### M1：分析与通知闭环

目标：

- 完成基础股票分析能力
- 支持结果结构化输出
- 支持至少一种通知渠道
- 支持基本定时任务执行

交付结果：

- CLI 可运行
- 每日分析可推送
- 报告结构初步稳定

### M2：Web 工作台成型

目标：

- 上线 Web 查看与配置入口
- 支持手动分析、历史报告、基础设置
- 建立分析任务与报告查看的完整前端链路

交付结果：

- 首页、历史、设置等核心页面上线
- 支持完整报告查看与重新分析

### M3：Agent 与回测增强

目标：

- 增加策略问股能力
- 支持多轮会话和技能选择
- 增加历史结果回测验证能力

交付结果：

- 问股页上线
- 回测页上线
- 历史分析与回测形成关联

### M4：持仓与投资闭环

目标：

- 增加持仓账户与交易事件管理
- 将分析结果与持仓管理串联起来
- 强化从“分析”到“执行跟踪”的闭环

交付结果：

- 持仓管理页面与 API 完整上线
- 支持账户、交易、查询、删除等操作

### M5：多用户与权限体系

目标：

- 建立注册、登录、角色权限和数据隔离能力
- 管理员与普通用户能力分层
- 支持 Bot 账号与内部用户绑定

交付结果：

- 多用户登录系统上线
- 管理员配置页和用户管理能力上线
- 用户级数据边界明确

### M6：多端与产品化增强

目标：

- 强化桌面端体验
- 优化移动端适配
- 提升系统在多部署环境下的一致性和易用性

交付结果：

- Electron 桌面端持续可用
- WebUI 交互体验更完整
- 文档、部署和升级体验进一步标准化

- 保证通知推送稳定
- 保证 Web 核心页面可用

### P1

- 强化持仓与分析联动
- 强化问股与历史报告联动

## 12. 成功指标建议

- 日均分析任务数
- 活跃用户数
- 历史报告查看率
- 问股使用率
- 回测使用率
- 通知送达成功率
- 用户配置完成率

## 13. 结论

股票智能分析系统的长期方向，不只是生成一份“每日股票报告”，而是构建一个围绕“分析、判断、验证、跟踪”的 AI 投资辅助平台。

未来版本应继续围绕以下三条主线演进：

- 更稳定的分析结果与通知触达
- 更完整的用户闭环和数据闭环
- 更强的多用户产品化和多端协同能力
